# Synomic Design System

A small, opinionated design system for **Synomic** — a Frisian ZZP-onderneming based in Heerenveen that helps Dutch MKB-bedrijven on the intersection of finance, IT and AI-automation.

> *Sync* (synchronisatie: systems, processes and people in step) + *Nomic* (the economic value that surfaces when an organisation is actually in order).

The system distills the live site into reusable building blocks: tokens, components, a website UI kit and one landing-page template. Everything is composable, lightly opinionated, and stays true to the source — navy authority, a single cyan accent, generous Frisian breathing room.

## Content fundamentals

Synomic writes in **Dutch**, addresses the reader as **"u"** (formal), and refers to itself in the third person ("Synomic doet…", "Synomic werkt met…"). The tone is **nuchter** (sober, no-nonsense — the Frisian sales register), confident but never hyperbolic.

- **Sentence shape:** short, declarative. "Niet andersom." "Geen hype, maar concrete toepassingen die werken." No exclamation marks. Almost no rhetorical questions.
- **Voice:** mixes a few English tech terms into Dutch sentences without translation — *forecasting, dashboards, LLM, RAG, OCR, RPA, BPMN*. Don't translate these into Dutch even if a translation exists; the site uses the industry words. Other terms (*automatisering, procesoptimalisatie, kennisbank, koppeling*) stay Dutch.
- **Hero copy pattern:** big claim, one cyan-highlighted phrase. *"Slimme oplossingen voor **digitale groei**"* — *"Wat ik voor u **doe**"* — *"Neem **contact** op"*. Use this exactly: H1 + a single `<em>` (rendered cyan, font-style normal).
- **Service / value tile pattern:** one-word adjective title ("Resultaatgericht", "Verbindend", "Innovatief", "Betrokken"), then one or two sentences. ≤180 chars.
- **Project tile pattern:** *Verb + measurable outcome*. *"Verwerkingstijd teruggebracht van 3 uur naar 10 minuten."* / *"Datakwaliteit verbeterd met 40%."* / *"60% van terugkerende vragen zelfstandig beantwoord."* Numbers earn their place.
- **Section-label / eyebrow pattern:** 1–3 words, uppercase, .14em tracking. *"Wie zijn wij"*, *"Specialisaties"*, *"Het verhaal"*, *"Klaar voor de volgende stap?"*.
- **CTA copy:** verb-first, optional →. *"Bekijk diensten"*, *"Stuur een bericht →"*, *"Start een gesprek →"*, *"Neem contact op"*.
- **No marketing fluff:** the words *"innovative solutions"*, *"revolutionary"*, *"cutting-edge"*, *"world-class"* do not appear on this site and should not appear in Synomic copy you generate. *"Praktisch"* and *"meetbaar"* do.
- **Numbers and references:** KVK 94705569; Koornbeursweg 73, 8442 DJ Heerenveen; reactietijd binnen 1 werkdag.

## Visual foundations

The brand reads **calm, technical, slightly cool**. Everything reinforces "competent professional in a quiet office".

### Color

- **Navy `#1B3A5C`** carries authority — used for body text, primary surfaces (footer, hero gradient), the form submit button. Two darker shades (`#0E2136`, `#1A4D6E`) compose the hero gradient.
- **Cyan `#2BC4C4`** is the only accent. Reserved for: section labels, the `<em>` highlight inside H1s, primary CTAs, focus rings, the pulsing badge dot, tag tints, the network-node logo glyph, hover-state highlights inside cards. **Never** dominant as a background — always small, deliberate, present.
- **Neutrals** are cool — slight blue cast in the off-whites (`#F8FAFC`, `#F5F7FA`) and borders (`#DDE3EC`, `#E8EDF3`). Warm beige is wrong for Synomic.
- **No additional accent hues.** No purple, magenta, green, orange. If you need a second tier of emphasis, use *muted* (`#6B7A8D`), not another colour.

### Type

- **Display:** Syne 600/700/800. Used for ALL headings, button labels, footer column headers, stat numbers. Bold 700 by default; 800 for the hero H1 and big stats. Tight tracking on the largest sizes (`-0.02em` on `.headline-xl`).
- **Body:** DM Sans 400 with 1.65 line-height. Light 300 italic is available but barely used.
- **UI labels:** DM Sans 500/700, often uppercase with `.10–.14em` tracking. These small caps are everywhere — section eyebrows, tags, nav-CTA tracking, footer headers.
- **Pairing rule:** never mix Syne body or DM Sans display. Buttons are the one exception — they use Syne even though they're small, because they read as brand objects.

### Backgrounds

- **The hero gradient** — `linear-gradient(135deg, #0E2136 0%, #1B3A5C 60%, #1A4D6E 100%)` — is the signature dark surface. Paired with two cyan radial glows (top-right large, bottom-left smaller) and a cyan dot-grid (`radial-gradient(circle, rgba(43,196,196,.15) 1px, transparent 1px) 0/48px 48px`).
- **Light sections** alternate between pure white and `--color-off-2` (`#F5F7FA`). The "Novictus-refined" section uses an even lighter `#F8FAFC` with hairline borders top and bottom.
- **No full-bleed photography**, **no hand-drawn illustrations**, **no repeating patterns or textures**, **no organic shapes**. The brand is geometric: dots, radial glows, network-node diagrams.

### Cards & containers

- **Default card:** white, 1px `#DDE3EC` border, **16px radius**, `36px 32px` padding. On hover: `translateY(-5px)`, larger navy-tinted shadow, plus a cyan→navy gradient bar slides in along the top edge (3px tall, animated in via opacity).
- **Light card variant:** softer `#E8EDF3` border, no top gradient. Used in "Novictus-refined" sections.
- **Form / feature card:** **20px radius**, deeper padding (44/40), navy shadow already at rest.
- **Dark card:** navy gradient background (135deg), used for the over-ons KVK stat panel and similar.
- **Tags / badges:** **40px capsule**, cyan-tinted background, uppercase .06em tracking. The hero badge uses a 1px cyan-translucent border plus a 7px pulsing cyan dot at the start.

### Shadows

All navy-tinted — `rgba(27,58,92, .04 → .16)`. **Never black**. Black on this cool palette reads wrong.

- `shadow-sm` (`0 2px 20px / .06`) — nav bar at rest
- `shadow-md` (`0 4px 32px / .10`) — form card
- `shadow-lg` (`0 12px 60px / .16`) — card hover lift
- `shadow-cyan-rest / -hover` — only under primary CTAs, only behind cyan

### Borders

1px hairlines (`#DDE3EC`) for cards. 1.5px (`#DDE3EC` → cyan on focus) for form inputs. 2px on the outline button. No double borders, no dashed borders (except the dashed line **inside** the canvas finance chart, drawn programmatically).

### Radii

`10` (inputs/buttons) · `12` (icon tiles) · `14` (partner pills, small icon containers) · `16` (default card) · `20` (feature blocks, form card, CTA banner) · `40` (capsules: tags, badges, filter buttons). Avatars and dots are full circles (`50%`).

### Motion

- **Reveals** — opacity 0 → 1, translateY 24px → 0, 650ms ease-out. Triggered by IntersectionObserver at 12% threshold. Drop `.reveal` on anything; flip `.visible` when in viewport.
- **Hovers** — translateY `-1` (nav CTA) to `-5` (default card) px. Always paired with a shadow change. 200–250ms.
- **Hero entrance** — staggered fade-up at 100/200/350/500/650ms.
- **Pulsing dot** — opacity 1 ↔ .5 + scale 1 ↔ 1.4, infinite 2s. Used on the hero badge only.
- **No bounce, no overshoot, no rubber-band easing.** Default easing is plain `ease-out` or `cubic-bezier(.22,.61,.36,1)`. The brand reads competent, not playful.

### Press / active states

Buttons drop their `translateY` lift on `:active` (return to baseline). Cards don't have a discrete press state — they're not buttons.

### Transparency and blur

- The nav bar at rest is `rgba(255,255,255,.95)` with `backdrop-filter: blur(12px)` on inner pages, solid navy on the homepage.
- The footer brand-name uses `brightness(0) invert(1)` on the white logo to keep it pure white on the navy.
- Translucent text scale on the dark hero: `.75` body, `.55` micro, `.35` ultra-quiet (the breadcrumb slash).

### Layout rules

- Page edges: `6vw` horizontal (`5vw` tablet, `4vw` small mobile). Don't use fixed pixel page padding.
- Section vertical padding: 80px desktop, 96px on the "clean" sections, 56px tablet, 44px small.
- Nav is `position: fixed`, 72px tall. Pages above-the-fold should account for the 100px first-section padding-top to leave room.
- Standard 3-up grid: `repeat(auto-fit, minmax(280px, 1fr))` with 28px gap. Collapses to 1 column under 768px.
- Forms use a two-column grid for short rows (naam+bedrijf, email+telefoon), collapsing to one column on mobile.

### Iconography

**Synomic uses three things only — there is no SVG icon font.**

1. **Inline emoji** — used as small functional icons on UI lists (`📍 💬 ⏰ 🔒 ✉️ ✅ ⚠️`) and as accent icons inside service / value cards (`🎯 🔗 💡 🤝`). Sized 1–1.4rem inline, or placed in a `54×54` cyan-tinted `.card-icon` square.
2. **Project tile emoji** — single large emoji centered on a navy gradient block at the top of each ProjectCard (`📊 ⚙️ 🤖 📈 🔍`). Size: `3rem` on `160`-tall tile.
3. **Animated canvas widgets** — the brand's actual "icons". Each home-page service tile and each `diensten`-page row pairs with a hand-coded canvas: bar chart (finance), network topology (IT), neural-net pulse (AI), process loop (procesoptimalisatie). They're decorative and recreating them is optional — but they're the *distinctive* part of the brand visual.

Things Synomic does **not** use:
- No Heroicons / Lucide / Material icons / Font Awesome — the system is intentionally without an icon font.
- No hand-drawn SVG illustrations — the logo's network-node mark is the only bespoke vector graphic.
- No emoji on slides or in body copy. They're a UI device, not decoration.

If you need a "settings cog" or "search magnifier" type icon, ask before adding — the brand prefers labelled buttons over icons.

### Imagery

There **is no imagery** on the live site — no team photos, no product screenshots, no stock photography, no hero illustration. The visual heft comes entirely from typography, the navy gradient, dot grids, and the animated canvases. If a Synomic page needs an image, ask the user to provide one first; do not generate or invent images.

## Notes & substitutions

- **Fonts.** The system points `tokens/fonts.css` at Google Fonts (`@import`), matching the live site. If you want self-hosted `.woff2` files for production, drop them in `assets/fonts/` and replace the `@import` with explicit `@font-face` rules.
- **Network-node logo mark.** The logo PNG ships with the cyan node-mark baked in. There is currently **no standalone SVG** for the mark — if you need the mark detached (e.g. as a favicon at small sizes), ask Synomic for a vector copy.
- **Animated canvas widgets.** Recreating these wasn't in scope here; the UI kit shows the design without them. The original implementation lives in the GitHub repo above — copy from there if you need a real one.
